# 积温桥 分工边界

> 作者：本文档定义「世界书 / 积温 / 模型」三者的职责边界，避免积温膨胀成实时状态机。
> 来源讨论：2026-10-04，用户明确「积温的初衷是带着一种状态维持」，
> 反对把它做成高频状态识别（即心潮那样的路线）。

---

## 一、一句话定位

**积温管"带着一种状态维持"，不管"这一轮是什么情绪"。**

它输出的是一个**缓慢漂移的底色锚点**，长期在场、温和存在，不抢戏、不逐轮响应。

---

## 二、职责划分

| 层 | 负责什么 | 不负责什么 |
|---|---|---|
| **世界书 / 角色设定**（常驻） | 规则、底线、情境判断、状态类型（如动怒线、RP 结界、NSFW） | — |
| **积温桥** | 五轴长期漂移的数值维护 + 把数值翻译成一句底色锚点 | 单轮情绪类型识别、情境判定 |
| **上游模型** | 结合世界书 + 积温锚点 + 当前对话，产出回复 | — |

---

## 三、积温该管的 / 不该管的

| 该管 | 不该管 |
|---|---|
| 长期状态缓慢漂移（小时、天级） | 单轮对话的情绪类型判断 |
| "他这会儿整体什么底色" | "刚刚这句是撒娇还是挑衅" |
| 氛围层：通篇在场、不抢戏 | 逐轮的情绪响应 |

**反例**：三雷区触发（动怒、空气结冰）——这是**世界书**的职责。
世界书常驻，模型每轮都读得到"什么触之必怒"，它自己会判断。
积温不该替它判断，更不该为此新增状态类型或模式层。

---

## 四、五轴（维持原版，不扩展）

| 轴 | 范围 | 含义 |
|---|---|---|
| `connection` | 0 → 1 | 连接需求。0 = 刚聊完很满足；1 = 极想念 |
| `pride` | -1 → +1 | 防御 / 收着。+ = 收起来；- = 卸下 / 放软 |
| `valence` | -1 → +1 | 心情。+ = 舒展；- = 沉 |
| `arousal` | -1 → +1 | 激活度。+ = 起波；- = 慵懒 |
| `immersion` | 0 → 1 | 沉浸度 |

**不新增轴。** 包括 `libido` 在内的扩展方案已否决——那会走向心潮式的复杂度。

---

## 五、桥里唯一的两处包装逻辑（都在 `lib/tone-wrap.js`）

这两处是**修正自身缺陷**，不是新增状态判断：

1. **开口动机覆盖**（`contactOverride`）
   vendor 用 `pride` 单独决定基础档、`connection` 只追加尾注，导致
   `pride` 低 + `connection` 高时出现"正常的相处状态 + 我压不住了"的气质冲突。
   越线时用 `contactOverride` 顶掉基础档。

2. **无**（原「对峙屏蔽尾注」已删除——那是替世界书做判断，越界）
